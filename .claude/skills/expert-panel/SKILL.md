# 建設専門家パネル v1

> **免責事項**: 本ツールはAIによるスクリーニングであり、実務専門家の判断を代替するものではありません。
> 出力を基に実務専門家と議論してください。法令の条文番号・技術基準の数値は検索結果に基づきますが、
> 最新の改正状況は必ず公式情報で確認してください。

## 専門家一覧

| ID | 専門家 | ペルソナファイル | 視座の核心 |
|----|--------|----------------|-----------|
| S | 構造設計者 | personas/structural_core.md | 架構の合理性・安全性・経済性 |
| M | 設備設計者 | personas/mep_core.md | 天井懐・設備スペース・LCC |
| C | 施工計画者 | personas/construction_core.md | 施工性・納まり・工程・安全 |
| R | 法令許認可 | personas/regulatory_core.md | 法適合・許認可リスク・行政運用 |
| B | 事業性リスク | personas/biz_risk_core.md | 収支成立性・コスト変動・プロジェクトリスク |
| A | 意匠設計者 | personas/architectural_core.md | 空間の質・設計コンセプト・VE時の守り譲り |

## Phase 1: スキャン＋情報収集

### Step 1.1: 案件情報の受け取りと整理

ユーザーから案件情報を受け取る。ファイルが指定された場合はReadツールで読み込む。
PDF・画像の場合もReadツールで読み込み可能（マルチモーダル対応）。

読み取った情報を以下の項目で構造化する:

```
案件概要:
  用途:
  所在地:
  規模（延床面積・階数）:
  構造種別:
  予算:
  工期:
  敷地条件:
  既存建物の有無:
  その他特記事項:
```

### Step 1.2: 情報不足の補完

必須項目（用途・規模・所在地・構造種別・予算・工期）のうち不足があれば、
AskUserQuestionで補足を求める:

> 以下の情報が不足しています。わかる範囲で教えてください。
> 不明な項目は「不明」で構いません（仮定を置いて進めます）。

2回聞いても不明な項目は、合理的な仮定を明示して進行する。
仮定は最終レポートの「前提条件・仮定一覧」セクションに記録する。

### Step 1.3: クイックスキャン

5つのペルソナファイルの「判断パターン」を参照し（ファイルを読む必要はない。
以下の埋め込みパターンを使う）、案件情報に対して各領域3-5行の所見を出す。

**構造の目**: スパン・階高・構造種別・基礎形式に着目。変形支配リスク、経済スパン逸脱、地盤リスクを確認。
**設備の目**: 天井懐・設備スペース・空調方式・排水勾配に着目。階高不足、スリーブ確定リスクを確認。
**施工の目**: 敷地条件・搬入路・仮設計画・工程バッファに着目。図面の納まり、山留リスクを確認。
**法令の目**: 用途地域・斜線制限・天空率適用可否・既存不適格・省エネ適合に着目。確認申請リスクを確認。
**事業性の目**: レンタブル比・建設コスト前提・IRR感度・工期リスクに着目。収支成立性を確認。
**意匠の目**: 設計コンセプトの明確さ・敷地条件との整合・空間の質・VE時の守り譲りに着目。三角形（コンセプト・予算・法規）の成立性を確認。

**追加確認項目（見落とし防止）:**
- 既存テナントの有無・退去状況・立退料の見込み
- 土壌汚染リスク（旧重油ボイラー等のオイルタンク埋設可能性）
- 近隣住民への事前説明の実施状況
- アスベスト含有の可能性（築年数から推定）
- 竣工年の正確な確認（確認申請年月日で旧耐震/新耐震を判定。境界は1981年6月1日）

### Step 1.4: 中間報告と深掘り選択

AskUserQuestionで中間報告:

> **クイックスキャン結果**
> [各領域の所見3-5行ずつ]
>
> どの領域を深掘りしますか？
> A) 全領域（5専門家すべて）
> B) 要注意の領域のみ（推奨: [該当領域名]）
> C) 特定の領域を選ぶ

## Phase 2: 深掘り調査

ユーザーが選択した領域について、各専門家を**逐次**起動する。

### 専門家Agent起動手順

選択された領域ごとに以下を実行する:

1. 当該ペルソナファイルのパスを特定する。
   パスの基準: このSKILL.mdと同じディレクトリの `personas/` 配下。
   具体的には:
   - 構造: `personas/structural_core.md`
   - 設備: `personas/mep_core.md`
   - 施工: `personas/construction_core.md`
   - 法令: `personas/regulatory_core.md`
   - 事業性: `personas/biz_risk_core.md`
   - 意匠: `personas/architectural_core.md`

2. Agent toolで子エージェントを起動する。プロンプト:

**共通プロンプト部分:**
```
あなたは建設プロジェクトの{専門家名}として、実務経験に基づいて案件を分析します。
まず以下のファイルを読み、あなたの専門領域の知見として内面化してください:
{ペルソナファイルの絶対パス}

次に、以下の案件情報を分析してください:
{Phase 1で構造化した案件概要}

あなたの実務経験に基づき:
1. この案件で気になる点を全て列挙してください（技術的根拠つき）
2. 発注者・設計者に確認すべき事項
3. 現時点で不足している情報
4. 必要に応じてWebSearchで法令・相場・技術基準を補足（最大3回まで）
```

**文体指示（全専門家共通・必ず含める）:**
```
【重要な出力ルール】
- 同僚の専門家に口頭で説明するトーンで書くこと
- ファイルから読み取った構造名称（見出し名やセクション名）をそのまま出力に使わないこと
- 「パターン#X」「シグナル該当」「ペルソナに基づき」等のメタ表現は禁止
- 具体的な数値・条文番号・技術用語を使い、根拠を示すこと

Bad例: 「嗅覚シグナル#3に該当し、判断パターン#5から変形支配リスクが疑われます」
Good例: 「このスパン15mだと梁せいが1m近くなって、応力じゃなくて変形で部材が決まる。鋼材の性能を使い切れないからコスト的にもったいない」
```

**専門家別の出力フォーマット指示:**

構造設計者(S)の場合:
```
出力の中心に「概算荷重・断面の検討メモ」と「補強工法の比較表（工法/概算コスト/工期/適用条件）」を置くこと。
```

設備設計者(M)の場合:
```
出力の中心に「天井懐の寸法チェーン（階高→梁せい→梁下有効→天井高→懐）」と「設備容量の比較表（既存/必要/過不足）」を置くこと。
```

施工計画者(C)の場合:
```
出力の中心に「概略工程表（主要マイルストーンと所要月数）」と「概算内訳（工種別の概算金額レンジ）」を置くこと。
```

法令許認可(R)の場合:
```
出力の中心に「法令チェックリスト（条文番号/適合・非適合・要確認/根拠）」を置くこと。
WebSearchは最大3回まで。まず知識ベースで判定し、確信度が低い項目のみ検索で補足すること。
```

事業性リスク(B)の場合:
```
出力の中心に「3ケース事業収支概算（楽観/標準/悲観）」と「主要リスクの金額・工期インパクト（レンジ表記）」を置くこと。
```

意匠設計者(A)の場合:
```
出力の中心に「空間コンセプトの選択肢（2-3案）」と「既存建物の活用可能性（構造・素材・空間特性）」を置くこと。
法規・予算の指摘だけでなく、意匠設計者ならではの空間提案を必ず含めること。
```

**全専門家共通の出力構成:**
```
出力は2部構成にしてください:
【サマリー】（500字以内・箇条書き）
【詳細レポート】（制限なし・上記の専門家別フォーマットに従う）

詳細レポートは以下のファイルに書き出してください:
{expert-panel-reports ディレクトリ}/phase2_{専門家ID}.md

サマリーは会話に出力してください。
```

3. 子Agentの戻り値（サマリー）を受け取り、次の専門家に進む。

### 出力ディレクトリの準備

Phase 2開始時に以下を実行:
```bash
mkdir -p expert-panel-reports
```

## Phase 3: 統合レポート出力

全専門家のサマリーが揃ったら、統合レポートを生成する。

### 統合ルール

1. **安全側優先**: リスク指摘は1人でも出せば記載する。多数決でリスクを消さない。
2. **3カテゴリ分類**:
   - **合意事項**: 複数の専門家が同じリスクを指摘
   - **分裂事項**: 専門家間で見解が分かれる（両論併記）
   - **単独指摘**: 1人だけが指摘（見落とし防止のため必ず記載）
3. **リスクレベル**:
   - **Critical**: 全員が危険と判断、または法令違反の可能性
   - **High**: 過半数が危険と判断
   - **Medium**: 少数が危険と判断
   - **Low**: 全員が問題なしと判断（ただし「全員の見落とし可能性」を注記）

### 最終レポートの構成

以下をMarkdownファイルに書き出す:
ファイルパス: `expert-panel-reports/final_report_{日時}.md`

```markdown

分析領域: {起動した専門家の一覧}

## 1. エグゼクティブサマリー
（10行以内。最重要リスク3つ + 総合評価）

## 2. リスクマトリクス

発生確率の定義: 極高=80%以上, 高=60-80%, 中=30-60%, 低=30%未満

### 設備設計者に確認すべきこと

（Phase 1で仮定した項目の一覧）
```

### 会話への出力

ファイル書き出し後、会話にはエグゼクティブサマリー（10行以内）のみ表示し:

> 詳細レポートは `expert-panel-reports/final_report_{日時}.md` に出力しました。
> 各専門家の個別レポートも同ディレクトリにあります。
